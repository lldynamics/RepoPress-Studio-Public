P18 对齐的是通用草稿和安全迁移的核心用户流程，不是 macOS 的多 Profile 草稿模型。通用草稿正文保存在应用私有数据库；从当前文章复制或移动时只读取已保存且仍与会话 SHA-256 一致的磁盘正文，向仓库导入时只写入当前已打开仓库并使用无覆盖路径。所有移动/复制先生成短时计划、再确认执行，批量路径冲突会阻止整批操作；撤销会在正文或目标文件继续变化时拒绝覆盖。跨站点复用需要先把文章放入通用草稿库，再由用户切换并确认目标仓库；不会自动搬迁附件、改写 Front Matter、运行站点脚本，或接受任意外部仓库路径。

P19 对齐 macOS 图片工作台的仓库资源浏览与复用：读取绑定当前仓库会话、图片数/字节/像素有上限，任何遗漏明确显示部分结果；图片预览与插入都会复验内容，切换仓库或关闭面板后旧请求失效。它不执行图片压缩、裁剪、删除、隐私清理、批量引用修复或 AI 图片生成。完整的现状与后续批次见 [macOS → Linux 对照清单](docs/macos-linux-parity.md)。

P20 对齐 macOS 操作日志的浏览、筛选和确认清空流程。日志最多保留 500 条，只包含固定动作、命令结果、完成时间、耗时和经已验证仓库根计算的 SHA-256 关联键；不记录正文、标题、路径、URL、凭据或原始异常。独立私有 JSON 文件限制为 1 MiB，目录/文件权限分别为 `0700`/`0600`；持久化不可用时明确降级为本次运行的内存记录，日志失败不改变原命令返回结果。清空仅删除打开确认时已加载序号及以前的日志，新完成的操作保留，业务数据不受影响。当前仅覆盖 17 类显式执行命令；尚未合并历史发布台账、AI/MCP/RSS/浏览器采集事件，也没有导出或可配置保留期，不能视为完整操作审计系统。浏览器演示明确禁用本地日志。

P21 增加独立于“最近仓库”的已保存站点登记表：每个规范仓库根一项、最多 32 项，以稳定 UUID 保存名称与路径；登记只接受当前已验证的仓库会话。修改绑定注册表 revision，存储损坏或写入失败时禁用修改并保留原状态。选择站点只发送 profile ID，后端重新验证目录并签发新会话；读取完成后再次检查编辑器与请求身份，期间新增输入不会被切换结果覆盖。当前站点由实际已打开仓库匹配，启动仍遵守“恢复上次工作区”设置。移除只删登记、允许空表，保留当前会话与所有文件/草稿；跨站点复制仍通过通用草稿库的计划与确认完成。本批没有引入 macOS 完整 SiteProfile 配置、配置复制、站点专属草稿归属、自动搬迁附件或脚本执行。

P22 复用图片清单与受保护的 Markdown 读取接口，在独立 Worker 中检查常见内联/引用式图片、空 Alt、站点公共路径及相对路径。先扫描图片，再点击“检查引用与 Alt”；报告纳入当前编辑缓冲区，支持搜索、状态/空 Alt/当前图片筛选和分页。切换仓库、重新扫描图片、修改缓冲区或关闭工作台后旧结果失效；分析可取消，20 秒超时停止，无同步回退。Markdown 扫描受内容目录、1,000 篇、单篇 4 MiB/合计 32 MiB 限制，最多输出 2,000 条引用，遗漏明确报告。HTML、wiki 嵌入、模板和嵌套引用块/列表代码等未完整覆盖；不验证外部图片、不判断可删除资产，也不修改正文、图片或附件关联。

P23 接通搜索结果、写作诊断、内容健康报告和发布中心本地写作检查到编辑器的定位。发布中心点击“检查当前文稿”后可逐项返回正文；它仅复用常见 Markdown 诊断，不代表完整发布预检。定位保留同篇未保存缓冲，跨篇沿用切换确认；编辑或仓库/文稿变化会作废旧目标，懒加载编辑器就绪后才选中并聚焦。

P24 补齐当前窗口的正文/冻结选区查找替换预览、固定大纲和文章属性字段定位。查找支持文字、全词与正则；全部替换需预览确认，正文范围排除 Front Matter，旧文稿或选项的结果不能回填新状态。大纲可折叠、随光标高亮，按编辑区域宽度放在侧边或上方。“属性 · SEO”显式生成本地报告并打开对应字段，新增固定链接/封面路径输入；字段输入保持焦点，所有修改仍由“保存”写盘。无 Front Matter 时不自动创建，有结构问题时不自动改写。完整 SEO、原始 Front Matter 视觉折叠和多窗口仍未覆盖。最新主线 `2d2858f` 的对照、P29–P46 已有实现、笔记/交换/发布恢复等差距，以及已退役目标修正见 [2026-10-02 差异报告](docs/macos-linux-comparison-2026-10-02.md)。

## 本地开发

需要 Node.js 24、npm、Rust 1.90，以及目标系统对应的 Tauri 依赖。Git 为只读状态和 diff 的可选依赖；真实站点预览还需要从受信任系统或用户工具目录安装 Zola 或 Hugo。PDF 文字层是可选 capability，需要系统安装 `bubblewrap` 与 `poppler-utils`；本地 OCR 还需要 `tesseract-ocr`、`tesseract-ocr-eng` 与 `tesseract-ocr-chi-sim`。工具、语言数据或沙箱不满足受信路径策略时，界面会禁用 OCR。

```bash
npm ci
npm run dev
npm run tauri dev
```

macOS 上的通过结果只证明当前主机可构建、测试和启动。Linux 支持必须以 Ubuntu CI 或真实 Linux 设备上的同一套检查及窗口验证为准。

Linux release CI 会在 Ubuntu 22.04 只构建一次 `.deb` 与 AppImage，记录 SHA-256 后把同一份不可变产物送入 Ubuntu 22.04/24.04 矩阵；两条基线都在隔离的 Xvfb/D-Bus 会话中分别验证两种产物确实出现可见 X11 窗口。启动耗时写入 `window-startup.json`，超过 20 秒会使验收失败；这是一条 CI 回归预算，不是产品 SLA。Deb smoke 后还会卸载包，并确认包拥有的二进制和 desktop 文件已消失；不会 purge 或检查用户 HOME 数据。AppImage smoke 使用 `APPIMAGE_EXTRACT_AND_RUN=1` 规避 FUSE 差异。

独立的 Wayland lane 会清空 `DISPLAY`、强制 `GDK_BACKEND=wayland`，在 Weston headless 上分别验证 1x 与 2x 输出，并要求 20 秒内从运行态 AT-SPI 树读到应用窗口及三个稳定控件名称。它证明原生 Wayland 连接、合成器缩放信息和基础可访问性桥接，不证明 GNOME/KDE shell、实体显示器观感、Orca 完整交互或中文输入法候选窗。后者必须按 [`docs/linux-release-acceptance.md`](docs/linux-release-acceptance.md) 的五行风险矩阵采集与同一产物 SHA-256 绑定的真机证据；validator 对未知字段、缺行、非 `pass`、路径逃逸、附件复用、数量/大小与哈希不符全部 fail-closed。

可离线运行 `bash scripts/ci/smoke-linux-deb-window.sh --help`、`bash scripts/ci/smoke-linux-wayland-atspi.sh --help`、`bash scripts/ci/check-deb-uninstall.sh --help` 和 `python3 scripts/ci/validate-updater-manifest.py --help` 检查参数门禁；实际 GUI/AT-SPI 启动仍需具备相应运行时的 Ubuntu runner 或 Linux 设备。

真实 PDF 沙箱集成测试会在 Ubuntu 22.04 与 24.04 两条 CI 基线上运行，分别覆盖系统打包的 Bubblewrap + Poppler 文字层路径，以及 Bubblewrap + pdfinfo + pdftoppm + Tesseract 中英文数据路径。

`npm run check:version` 是发布前的版本一致性门禁，会比较 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json`。`NO_STRIP=1` 用于规避 linuxdeploy 内置旧版 `strip` 无法识别现代 Linux ELF `SHT_RELR` 节的问题；最终 AppImage 仍由 SquashFS 压缩。Linux 打包目前只声明 deb 和 AppImage；产物能生成不等于 Linux 支持已经成立。任何支持声明都必须同时有 Ubuntu 基线上的安装、启动、中文路径仓库、保存/冲突检测、卸载或升级，以及 Wayland/X11 窗口验证证据。

## 安全边界

Rust 后端只接受打开仓库后签发的 `sessionId` 和 `documentId`。Markdown 路径必须位于仓库内，绝对路径、父目录穿越、`.git`、符号链接、非 UTF-8 内容和超过 4 MiB 的文档会被拒绝。正文搜索最多读取 64 MiB、单文件最多 4 MiB，并限制查询、深度、文件数和结果数。

内容健康扫描只接受已打开仓库的 `sessionId`，使用该会话固定的仓库根和内容根，不接受前端提供任意扫描路径。它忽略符号链接和构建目录，最多访问 100,000 个目录项/Markdown 文件、返回 1,000 篇、读取 32 MiB，且单篇仍为 4 MiB；只解析 UTF-8/UTF-8 BOM，SHA-256 基于原始字节。任何编码、读取、路径或容量遗漏都会把报告标为部分结果并给出有界原因，不能被显示成“健康通过”。扫描只把有界正文返回本机 WebView 的专用 Worker 做确定性分析；Worker 不可用时拒绝分析，不同步降级到界面主线程。该流程不写应用状态或仓库，不运行 Git、站点工具、网络请求或 AI。

工作区状态只写入 Tauri 分配的应用数据目录：目录权限为 `0700`、状态文件为 `0600`，使用同目录临时文件、同步与原子替换。状态最多 5 MiB，只包含设置、最近路径和一个最多 4 MiB 的恢复稿，不包含仓库/AI 凭据、语义索引或 PDF 内容。恢复稿绑定仓库、文档和磁盘 SHA-256 基线；磁盘内容变化后只能有界预览或丢弃，不能一键应用。关闭恢复功能会同时清除现有恢复稿。

草稿历史使用应用数据目录下权限受限的独立 SQLite，仓库键只来自已验证会话根，不接受前端路径作为文件系统权限。保存前和恢复前先持久化当前磁盘版本；删除时先提交回收副本，文件删除失败则回滚新副本，崩溃窗口宁可留下重复恢复副本也不丢失正文。回收恢复只能创建尚不存在的仓库内 Markdown 路径；永久删除只清理该草稿的私有回收副本、版本与身份，不删除任何仓库文件。

Git 状态与 diff 都不经过 shell；diff 禁用 external diff 和 textconv，并把 staged/worktree 总输出限制为 512 KiB。真实站点预览只支持 Zola/Hugo，要求每次显式确认可信仓库，仅绑定 `127.0.0.1`，工具必须来自固定受信任目录且不能位于仓库内；嵌入页面使用跨源 sandbox，不获得 Tauri IPC 或同源权限。预览仍会让本机 SSG 处理仓库内容，因此不要对不可信仓库启动。

Git 写操作同样不经过 shell。计划默认五分钟过期且只能执行一次，执行前会重新验证仓库根目录、session、HEAD、分支、index、远端 URL 和相关引用。选择性暂存最多接受 100 个显式路径，拒绝穿越、`.git`、符号链接、rename/copy 和超过 4 MiB 的文件；它从 `O_NOFOLLOW` 稳定文件描述符读取原始字节，以 `hash-object --stdin` 和单次原子 `update-index` 写 index，不向 Git 传入待过滤的文件路径，因此仓库 clean/process filter 不会运行。取消暂存和两种暂存操作都不改工作树。Commit 只处理用户已经暂存的内容，并要求仓库自身配置 `user.name` 与 `user.email`，不会隐式加载不受审查的全局 Git 配置；fetch 只更新远端跟踪引用；push 只推送当前分支到同名分支并禁用 force、hooks 和递归子模块。HTTPS 令牌通过进程内 askpass 传给 Git，不进入命令行或错误；SSH 只允许系统现有的批处理凭据。

仓库令牌使用固定、可信的 `secret-tool` 和当前用户的受验证 D-Bus session bus。Secret Service 锁定、缺失或失败时只保存在当前进程内存，界面会明确标记；令牌不会回读给前端或写入仓库。deb 将 `libsecret-tools` 作为推荐依赖，AppImage 不捆绑密钥环实现。

AI 凭据使用独立的 `repopress-ai` Secret Service namespace，不会与 GitHub/GitLab 仓库令牌混用。外部 provider 只允许无 userinfo、query、fragment 的外部 HTTPS 基础地址，本机 Ollama 只允许 loopback；HTTP 客户端禁用环境代理与重定向，并限制连接时间、总时间和响应大小。密钥环缺失、锁定或写入失败时，AI 凭据明确降级到本次进程内存；若无法确认旧的持久凭据状态，界面会单独提示。选区编辑计划绑定 provider、endpoint、model、指令、文档 revision 与精确 UTF-16 选区，五分钟过期且一次性消费。只有指令和最多 64 KiB 的选区会离开编辑器；完整文档不会发送。模型输出必须通过严格 JSON、UTF-16 边界、原文匹配、数量、大小和重叠复验，接受后也只修改尚未保存的缓冲区。连续对话同样为每轮生成五分钟、一次性的发送计划，绑定当前会话、消息、服务配置和显式选择的资料版本与内容摘要；执行前重新检查权限、版本和内容，任何漂移都会拒绝发送。每轮最多选择 8 条已授权资料，资料正文合计最多 64 KiB；资料被作为不可信参考数据隔离，不会自动检索。对话和计划只存在于当前进程内存，发送失败不会把待发送消息写入会话。

离线语义索引限制扫描深度、目录条目、文件数、chunk 数、单文件 4 MiB 与每次 64 MiB 总读取量，跳过 `.git`、构建目录和符号链接；文件通过 `O_NOFOLLOW` 稳定描述符有界读取并复验路径与前后 metadata，索引、查询和 chunk 只保存在进程内存，切换仓库即清除。PDF 选择令牌最多有效五分钟，且只能二选一执行文字层提取或 OCR；所有成功/失败路径都先消费令牌。令牌绑定 canonical path、设备、inode、大小、修改/状态时间和完整 SHA-256，处理时从稳定描述符生成匿名、不可改写的密封 memfd，Bubblewrap 仅以 `--ro-bind-data` 只读绑定快照，不再打开原始用户路径。OCR 先用沙箱内 `pdfinfo` 复验页数，拒绝超过 12 页；每页由沙箱内 `pdftoppm` 生成不超过 2400 像素边长、16 MiB 的 PNG，再写入新的密封 memfd 交给另一沙箱内的 Tesseract。语言只允许英语、简中或两者组合，汇总文字最多 8 MiB。所有文档工具及语言数据必须来自 root 所有且不可被 group/world 写入的固定系统路径；子进程清空环境、断网、不经 shell，并受墙钟、CPU、地址空间、进程/FD、文件和输出上限约束。OCR 结果只显示在当前面板并可由用户复制，不会自动写入仓库、语义索引或发送给 AI。AppImage 不捆绑这些工具。

资料库位于应用数据目录的独立 `knowledge-v1` 区域，目录权限为 `0700`、清单和内容/归档对象为 `0600`，使用内容 SHA-256、`O_NOFOLLOW`、有界读取和原子清单替换。清单 schema v4 兼容读取旧数据，旧条目迁移后远程 AI 权限一律为关闭；最多保存 128 个分类、每条资料 32 个版本，所有历史正文与归档都计入容量和垃圾回收引用。单条文字最多 5 MiB，总文字库最多 64 MiB/2000 条；单个离线归档最多 24 MiB，归档对象合计最多 512 MiB。来源 URL 仅允许无账号密码的 HTTP/HTTPS，并移除 fragment。基本全文检索完全在本机运行；本机语义索引与远程发送权限相互独立。资料正文只有在用户逐条授权、在当前对话轮次中显式选择并再次确认发送计划后才可进入远程请求；离线归档永不进入 AI 上下文。离线归档不进入检索正文，也不会在应用内执行或联网加载。Markdown 与归档导出都只允许当前已打开仓库内尚不存在、扩展名匹配的相对路径，并要求生成和再次确认短时一次性计划。

浏览器采集桥只绑定 IPv4 回环地址，使用 32 字节随机令牌并每 24 小时过期；请求必须同时通过 Host、已登记 Chrome/规范 Firefox 扩展 Origin、Bearer 令牌和协议头校验。正文最多 5 MiB；完整网页归档必须使用标准 Base64、声明为 `html` 或 `mhtml`、通过对应格式特征复验且解码后不超过 24 MiB，格式、数据与完整性报告不一致时整次导入失败且不留下半成品。同一标准来源网址会在写入前返回结构化冲突，只有用户明确选择保存新版本、仅移动分类或保留副本后才继续；operation ID 与请求指纹的完成账本最多保留 256 项、30 天，重试只重放不含正文/归档的原回执。扩展传入的远程 AI 权限默认关闭，并纳入请求指纹和完成回执；仅移动分类会保留原资料权限，不会被新请求改写。端口占用时主程序继续启动并明确标记采集不可用，配对令牌可在资料库界面手动轮换。

## 签名 AppImage 更新

签名流程只接受精确等于 `v<package.version>`、且 commit 位于 `origin` 默认分支历史中的 tag。公开的 Tauri/minisign 公钥和 HTTPS manifest endpoint 通过 `REPOPRESS_UPDATER_PUBKEY`、`REPOPRESS_UPDATER_ENDPOINT` 提供；manifest 中的精确 AppImage 下载地址使用 `REPOPRESS_UPDATER_APPIMAGE_URL`。先做无副作用配置检查：

```bash
npm run check:updater
```

`npm run build:updater` 只允许无私钥构建，并在检测到任何签名私钥环境变量时失败。手动 GitHub Actions 工作流 `.github/workflows/tauri-linux-updater.yml` 依次执行可信 tag 策略、完整前后端与离线发布契约测试、无私钥 AppImage 构建和 `linux-release-signing` 受保护 Environment 中的唯一签名步骤；私钥只能在该步骤通过 `TAURI_SIGNING_PRIVATE_KEY`（以及可选密码）出现。工作流随后用公开密钥真实验证 Tauri/minisign 的 artifact 与 trusted-comment 全局签名，把受签名保护的 `file:` 字段精确绑定到 AppImage basename，并校验 version、tag、唯一 `linux-x86_64` 平台、公共 HTTPS URL、RFC 3339 发布时间和产物文件名，最后输出含 SHA-256 和 signing key id 的 `updater-review.json`。它只上传待审核候选，不自动创建线上 Release，也不下载配置 URL。

配置正确的 AppImage 客户端只在用户点击“检查”后访问 manifest；发现更新时生成五分钟有效、一次性消费的审阅计划，展示版本、发布时间、下载 Host、产物名和有界发布说明。用户再次确认后才会有界下载，由内置公钥验证签名，并原子替换当前 AppImage；应用不会自动退出或重启，用户必须手动重启。Webview 没有直接调用 updater 插件检查、下载或安装的权限。普通未配置 build 保持 fail-closed：endpoint 为空、公钥为空、检查按钮不可用，不会尝试联网。

`.deb` 不走应用内更新，仍由软件源、系统包管理器或手动安装负责。当前没有后台定时检查、静默安装、自动重启、自动回滚或密钥轮换；仓库也没有真实生产 endpoint 或签名公钥，因此普通本地包不能完成端到端联网更新验证。

仓库管理员仍需创建并保护 `linux-release-signing` Environment（建议 required reviewers），把私钥只保存在其 Environment secrets，配置上述公开变量，并从可信版本 tag 手动运行工作流。缺少这些外部设置时，代码存在不等于可发布。
