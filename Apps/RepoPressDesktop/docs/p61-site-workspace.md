# P61：阅读与站点工作区（2026-10-15）

本批实现 [Linux 完善计划](macos-linux-comparison-2026-10-13.md)的 P61 核心入口、站点总览和上下文隔离。保留 `rss` / `sync` 内部标识，对外展示“阅读 / Reading”和“站点 / Site”。这不是完整 macOS 工作区或原生平台验收结论。

## 用户可见行为

- “站点”进入当前仓库的总览，显示登记名称或仓库名称、原样根路径及站点类型。检查、发布和站点管理集中在三个入口；没有仓库时可选择仓库。
- 站点检查进入已有内容健康面板，仍需点击“扫描仓库内容”才读取 Markdown。发布沿用已有计划与确认流程，站点管理沿用已有登记及受保护切换。
- 发布、内容健康、管理站点的命令入口使用站点背景；关闭抽屉回到站点总览，定位内容问题则回到写作。工具面板的实际标签变化会上送路由状态，不以旧请求标签判断当前位置。
- 阅读页明确显示本机 RSS 范围，隐藏站点选择器。切出阅读页继续停止 P60 的自动刷新计时；没有扩展为应用级后台联网。
- 写作、阅读、站点往返保留编辑器实例和未保存缓冲区。不可见写作区同时设为 `hidden` / `inert`，只有当前可见区域拥有 `workspace-content` 跳转目标。真实站点预览离开写作时卸载并停止旧会话，未扩大 Hugo/Zola 执行范围。
- 总览宽窗三列、窄窗一列，内容独立滚动，长路径折行。首次进入聚焦标题，语言或仓库属性更新不重复抢焦点；同期打开抽屉时由抽屉管理焦点。

## 上下文与兼容保护

现有 `rss-workspace`、`publish`、`content-health` 和 `site-profiles` 命令 ID 保留，新增 `sync-workspace`。阅读命令描述仍包含 RSS，原搜索词继续可用。站点切换仍经过未保存确认和 `prepareRepositorySwitch` 的会话、文档、文本及请求代际复验，取消或等待期间产生新输入都会保留当前内容。

本次审查并修复两个相关生命周期缺口：

1. 发布抽屉关闭后不再因切换站点而加载凭据状态、浏览器协议状态、更新就绪或 Git 状态。关闭、卸载和换会话使旧响应失效；同会话重开重新加载，避免永久停在 loading。
2. 主工作区手动 Git 刷新在成功和错误路径均验证仓库代际与 session；旧站点晚到的结果不能覆盖新站点状态或通知。暂存、推送重试后的二段刷新同样复验代际。

没有新增 IPC、数据库迁移、依赖或后台扫描。完整站点配置模型仍属于 P65，多窗口上下文属于后续系统体验范围。
