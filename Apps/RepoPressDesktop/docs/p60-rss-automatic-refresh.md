# P60：RSS 自动刷新与本地交付基线（2026-10-15）

本批完成 [2026-10-13 计划](macos-linux-comparison-2026-10-13.md)的自动刷新修复，并收口本地源码、门禁和构建证据。自动刷新尊重已有刷新时间和失败退避，手动刷新保留显式强制请求。应用级后台调度仍是后续可选增量，既有设置保持“阅读工作区活跃时自动刷新”的范围。

## 刷新行为

- 自动计时明确调用 `refreshAll(false)`；手动全部/单订阅刷新明确传 `true`。Tauri Gateway 的省略参数默认值改为 `false`，Rust IPC 的 `force` 仍为必传布尔值。
- 偏好和快照成功加载后才启动计时；关闭偏好、离开活跃阅读页或卸载会停止未来计时。搜索、筛选、语言和普通重新渲染不重置周期。
- 每个 Gateway 只有一个在途刷新，锁在操作开始前取得，覆盖手动/自动和共享 Gateway 的重新挂载。慢请求期间后续刷新跳过，失败后释放锁，下一周期可再尝试。
- busy 状态由 Gateway 级控制器订阅；旧 Reader 卸载后仍能释放，新 Reader 不会永久卡在刷新中。
- 快照、列表和刷新响应绑定生命周期代次。inactive→active、A→B→A 网关切换、StrictMode 重放及卸载后，旧结果不覆盖新状态、不发起旧视图重载或预翻译。
- 完成时使用最新查询和预翻译偏好；手动操作保留完成反馈，自动刷新更新当前清单。历史补全的确认、来源和限额不变。

沿用已有 `next_refresh`、`next_retry`、失败次数和持久状态逻辑；未修改生产网络权限、数据库 schema 或历史任务格式。响应注入仅在 `cfg(test)` 编译，以实例级 transport 覆盖全部订阅工作线程。

## 交付基线收口

1. 精确格式化 `ai_connection.rs`、`ai_provider.rs`、`workspace_state.rs` 的 4 处既有差异，全库格式门禁通过。
2. 写作检查器首次打开时懒加载，之后保留输入状态。Ctrl-F 请求绑定文稿身份并执行后消费；切文稿/隐藏/专注模式会失效，保存后重新挂载不会再次抢走焦点。
3. 首屏 JS 从 698.7 KiB 降至 **677.9 KiB**，保留 **700 KiB** 门槛及必需延迟界面检查，余量约 22.1 KiB。
4. 共享 manifest 中全部 **5 条有效 YAML 产出样例**接入真实 TS 元数据解析/编辑和 Rust 元数据变换入口；Rust 同时验证样例 SHA。此切片验证跨端产出可读取、无操作时原字节保留，不宣称完整 renderer、TOML 表格、endpoint 或 diff 合同已经对齐。
5. 保存完整源码、依赖锁、工具链版本、逐文件摘要及可重放增量。本地开发基线仍不替代经过授权的远端提交、CI 或正式发布。
6. 从同一冻结源码构建 `.deb` 和 AppImage。本机 Fedora 的缓存 strip 不支持 RELR，使用已验证的 `NO_STRIP=1`；另从 AppImage 官方 GitHub 获取 runtime 并核对发布资产 SHA-256，通过 `LDAI_RUNTIME_FILE` 固定文件。首次打包失败日志保留，最终重打包成功。
