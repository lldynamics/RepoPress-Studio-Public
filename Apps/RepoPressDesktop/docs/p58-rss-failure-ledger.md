# P58：RSS 历史失败账本与分批重试

接续 [P57](p57-rss-history-completion.md)，以冻结的 `origin/main@878d8cc` macOS 历史补全合同为参照，补齐独立失败账本、失败不阻塞下一段发现，以及跨段、跨重启的有界失败重试。P57 中“必须先重试所有失败才能继续发现”的限制由本批替代。

## 使用与同意

当前候选处理完后，即使仍有失败项，也可以手动继续发现下一段历史链接。失败 URL 和原全文目标保存在独立本机账本中，切换候选段不会丢弃失败记录；累计发现、添加、全文补齐和重复计数继续保留。本段待处理项仍须先处理完；运行中或请求在途时不允许换段。

“预览失败重试”仅从本机账本准备最多 1–500 项预览，不访问网络、不导入文章。用户勾选新的确认并开始后，才逐项请求和写入。完成本段后，可预览下一批失败重试，或继续发现历史链接。关闭、重开和应用重启都不会自动联网重试。界面区分本段候选/待处理数与全任务未解决失败数；重试候选不重复增加累计发现数。编辑下一批数量上限会保留已加载检查点并清除确认，加载或执行期间禁止修改上限。

预览按精确 URL 排序，从持久游标之后选择；到末尾后回绕。因此前一批持续失败不会永久挡住后面的失败项。成功、已补全文或已确认重复后，仅移除对应 URL 的失败记录。失败继续留在账本，单个任务的未解决数按唯一 URL 计算。

## 持久化与安全边界

RSS 数据库升级至 schema 4，新增 `history_failures(job_id,url,candidate_json)`，主键为任务与精确 URL，外键随准确检查点删除而级联清除。失败写入/移除、文章或缓存写入、累计计数和检查点在同一事务中提交；转段也先原子保存旧段失败，再清空当前候选。仍最多保留 20 个任务，每任务最多 50000 个未解决 URL，每条失败记录最多 32 KiB，每次预览最多 500 项，检查点 payload 仍有 5 MiB 上限；超限或无效记录拒绝本次变更，保留此前状态。

schema 3 的旧检查点可读，当前失败项在首次变更时迁入独立账本；只读状态/列表不会写入迁移记录。数据库 schema 1–3 沿用既有迁移路径升级到 4，未知未来版本拒绝迁移。

全文失败记录携带原文章 ID、URL 和修订指纹。准备重试时只对仍匹配的目标刷新修订；原目标删除或改变身份时保持旧绑定，执行失败，不能把全文重试变成新增文章。当前来源已有 ready 缓存时零请求复用。未启用批量全文补齐的任务不会因重试获得全文写入权限；执行期间的目标、来源和缓存漂移仍拒绝旧结果。

待处理/运行中/在途任务、发现占用、订阅/站点/私网偏好漂移保持原有拒绝语义。预览本身允许在退避期间准备，真正发现和文章请求仍遵守 `nextRequestAt`、429/503 Retry-After、至少一秒间隔、robots、noarchive、同源公开网络、逐跳 DNS/peer 校验及响应大小限制。既有 `retryFailures` 参数仅兼容当前已审阅候选段，不加载账本中的额外 URL；新界面通过本地预览后调用普通文章步骤。

## 备份与对齐范围

JSON 备份接受数据库版本 2、3、4，仍排除历史任务和失败账本；JSON 恢复清空历史队列并级联清理账本。完整 SQLite 私有快照升级为 schema 4、十张表合同，包含 `history_jobs` 和 `history_failures`，继续要求预览、敏感明文确认、结构一致性、精确来源复验和不可覆盖写入。缺表、错误外键或未知结构拒绝导出。

macOS 已有独立失败表、处理失败后继续发现、最多 500 项按 URL 游标轮换重试。本批补齐这些行为；Linux 在网络执行前增加本地重试预览与重新确认。正文完整性保守判定、登录/查询参数分页、JavaScript 页面、跨域/压缩 sitemap 和无限扫描仍不在当前范围，达到上限不能视为全站历史已完整。
