# P34：统一只读发布台账

发布中心现在把 P31 Git 推送和 P32 PR/MR 持久记录放到同一只读视图，显示各自可证实的状态、冻结 SHA 和核实时间。打开或刷新台账只读本地数据；远端核实继续通过原记录面板的审阅与确认入口。

## 已实现范围

- 复用两份既有私有 SQLite 记录，不新增数据库、迁移或补造旧活动日志。重启后重新读取持久记录；以 `source + recordId` 区分记录，同一 SHA 的推送与 PR/MR 不合并为一次发布。
- 每次读取复验当前仓库目录、Git common-dir 身份和唯一推送 URL。允许本地 HEAD、暂存区和工作树已有后续变化，因为视图展示的是历史冻结提交；目标变化会覆盖旧的已核实状态。
- 推送已核实要求既有核实结果、核实时间及精确远端 SHA 一致。PR/MR 已核实要求既有关联证据匹配、核实时间、编号及精确官方 URL；没有新的网络观察，就不会增加新的成功证据。
- 分别显示推送已核实、PR/MR 已核实、未核实、远端不同、目标已变化、证据无法复核或不一致。远端不同只是上次查询的历史观察，不等同于推送失败；已核实也不表示合并、部署或网站上线。
- 每来源最多 200 条、合计最多 400 条；来源读取失败、超限或重复 ID 时整份来源不进入结果，并明确标记部分来源。摘要只统计已读记录；全部来源失败不会显示为完整空台账。面板每页 50 条。
- 前端拒绝来源、操作、状态矛盾、摘要不一致或非法身份/时间/数量的响应。仓库切换、关闭、网关变化和刷新版本变化立即隐藏旧快照，并丢弃过期响应；手动刷新防止重复请求。
- 记录可返回原推送或 PR/MR 面板并聚焦。原面板核实或清理结束后，以及既有推送、重试或评审创建结束后，统一视图重新读取本地记录，包括执行报错后可能已经落盘的结果。
- 用户手动查询部署后，可在同一仓库会话显示已有部署观察。当前部署接口没有冻结提交身份，因此观察不归因到任一台账记录，也不计入已部署或成功统计；打开台账不会自动查询部署。

## 接线与权限

[发布中心](../src/components/PublishCenter.tsx) → [台账面板](../src/components/ReleaseLedgerPanel.tsx) → [合同](../src/contracts/releaseLedger.ts) / [Gateway](../src/platform/repositoryGateway.ts) → `get_release_ledger` [命令](../src-tauri/src/commands/release_ledger.rs) → [本地投影](../src-tauri/src/core/release_ledger.rs)。命令只接收 `sessionId`，沿用受限仓库会话和已有存储；不接收目标 URL，不读取凭据，不调用远端观察，也不写入记录。

浏览器 demo 返回明确不可用的部分来源结果，发布中心不启用台账读取。远端核实、删除本地记录的权限与确认要求沿用 P31/P32；统一视图本身没有这些执行按钮。

## 保留边界与下一步

P34 是 P31/P32 的有界本地投影，不是完整 macOS ReleaseLedger。两份来源逐次读取，不构成跨数据库或文件系统原子快照；外部仓库变化需要重新刷新，历史已核实结果不证明当前远端仍相同。当前没有逐文件发布证据、精确部署关联、合并状态观察、回滚或撤回执行，旧日志不会升级为成功记录。

真实 GitHub/GitLab、原生窗口重启与 GNOME/KDE、Wayland/X11、HiDPI、中文输入法和 AT-SPI 矩阵尚未验收，本批没有构建或发布 AppImage/deb。

下一批建议 P35 只读回滚资格审阅：冻结记录身份与源提交，核对可恢复的本地对象和当前远端头，展示不满足条件的原因；资格报告不授权写远端。远端写入、全文与附件恢复另设可审阅的一次性执行计划。

同日后续已完成 [P35 基础资格审阅](p35-rollback-qualification.md)的单父提交/根树检查和确认式只读远端头查询。它不证明全部文件对象可恢复，也不执行回滚；逐文件预览与执行事务仍待后续。
