# P64A：重复标题诊断与有界检查会话（2026-10-16）

接续 [P63](p63-preview-readiness.md)，本批完成 [P64 写作完成度计划](macos-linux-comparison-2026-10-13.md)的第一项。Linux 原来已有简单重复标题告警，本次修正误判、补齐首个标题定位，并让长文检查可取消。正文统计会话与版本比较仍分批实施。

## 标题规则与定位

- 检查正文中行首至多三个空格、H1–H6 的 ATX 标题，正确区分闭合哈希与 `C#`、`Title###` 中的文字哈希。不完整解释列表/引用嵌套语境；Setext 标题及完整渲染后的可见文本等价判断不在本批范围。
- 标题身份取原始文本，仅作 NFKC、大小写和连续空白归一化；保留行内代码、转义符、下划线和星号。``API `foo` `` 与 ``API `bar` `` 不再因遮蔽代码而误报；格式不同但显示相同的标题可能不会归为一组。
- 排除 Front Matter（包括未闭合的 YAML/TOML）、围栏/缩进代码及识别到的 HTML 块、注释。HTML 状态独立处理，原始 HTML 内的反引号不会遮掉结束标记。
- 每个后续重复项指向第一次出现的标题，显示其原始行号；提供“定位”和“定位首个标题”。UTF-16 范围直接对应编辑器，保留中文、emoji、CRLF。重复项没有自动修复或改名，不宣称所有渲染器都会产生冲突锚点。
- 写作检查器、发布前文稿检查均按完整来源文本和文稿身份核验定位；只读稿仍可定位。过期结果立即隐藏，不能把旧范围应用到新文稿。原有标题层级快速修复仍只替换哈希。

## 检查会话

App 状态栏、写作检查器及发布前文稿检查使用同一个会话合同。发布检查仍需点击“检查当前文稿”；内容、文稿身份或文章索引变化后，必须重新请求。

- 不超过 32×1024 个 UTF-16 代码单元的小文稿保留同步诊断；更长且不超过 512×1024 的文稿，经 200ms 防抖后在模块 Worker 中检查，派发后五秒超时。
- 文稿超限或文章索引超过 20,000 项 / 合计 1,048,576 个 UTF-16 代码单元时明确显示未检查。Worker 不可用、构造/派发/返回失败、超时也明确显示失败或不可用，不回退到主线程检查长文。
- 取消、换稿、修改内容/索引、重试和卸载终止旧 Worker；来源、文稿、上下文与代次绑定，迟返成功/错误不能回填。改动后再改回原文不会恢复旧报告。未提交的 React 并发渲染不能使当前已提交检查失效。
- 有限诊断上限采用最大堆，按源码顺序保留最早的问题，保留结果内存为 O(上限)。会话取 501 项作为截断哨兵，仅返回 500 项；界面每次展示 50 项并明确提示截断，状态栏不会把截断计数当成完整计数。
- 只有当前 `ready` 会话才能显示零问题。等待、取消、失败、不可用和超限分别显示状态，仍能从状态栏打开检查器。

本批不新增后端命令、持久化格式、依赖或网络请求。统计、章节操作和查找替换仍沿用原有独立流程；本批 Worker 边界仅覆盖 Markdown 诊断，不表示整个编辑器的所有长文工作都已异步化。
