# P40：本地恢复证据归档

2026-10-02。固定 macOS 对照仍为 `origin/main = 2d2858fc5ebc3843d1a281026304c2551741691c`，Linux HEAD 为 `97f1fd75e12b4b9606974890bfa317a7bac9b6e3`。本批承接 P39，能力判断包含未提交的 Linux 实现；没有合并主线或重新拉取其他分支。

## 已实现

发布中心的“发布台账与手动恢复”新增“私有回滚证据归档”：选择新的 JSON 文件路径，明确生成预览，再勾选明文敏感信息确认，最后点击导出。取消路径选择不会生成计划或写文件；取消已生成计划会丢弃令牌并清空同意。空台账显示没有可归档证据，损坏或不可用存储不能导出部分记录。

预览只返回当前仓库范围、目标路径、总记录/首次候选仍未明/已有历史首次观察计数、字节数、SHA-256 和到期时间，不把完整私有台账送进界面。最多 200 条记录、8 MiB JSON；每个会话最多一个计划、全应用最多八个，五分钟失效。执行先消费令牌，再核对会话、根目录、全部本仓库记录和目标目录。台账任何本仓库增删或 revision/观察变化都会使计划失效；另一仓库的有效记录变化不扩大本仓库归档范围。全局任一损坏行仍使读取失败关闭。

导出包含完整冻结来源回执及 P38 的最新观察与历史首次观察，即使 P31 来源已被移除也能归档。JSON 的 `format` 为 `repopress-rollback-evidence`，`schemaVersion` 为 1，`capturedAtEpochMs` 是预览时的快照时间，`repositoryPath` 和 `records` 是该范围的历史证据。它不是数据库恢复包或已验证远端状态的证明；SHA-256 用于核对输出字节，不认证记录真实性。

明文包括仓库/文件路径、远端 URL、分支、记录/计划/会话 ID、SHA、时间和观察。没有文章正文或独立凭据字段；URL 本身可能含秘密，归档不会替用户脱敏。界面必须针对当前计划重新确认这些敏感范围，不能沿用旧路径、旧会话或旧刷新上下文的同意。

## 写入与原台账边界

- 仅 Linux 使用目录描述符逐组件打开父目录，拒绝符号链接、相对路径、父目录越界组件、已有文件/目录、当前仓库内目的地，以及其他用户拥有或组/所有人可写的父目录。不会创建缺失的父目录。
- 预览绑定父目录身份；执行重新核对，并通过保留的目录句柄写入私有临时文件，权限 `0600`。临时文件写入、fsync、读回确认后才不可覆盖地发布到新名称；再同步父目录、核对最终文件身份/权限/硬链接数/完整字节。
- 本地归档 I/O 期间持有恢复台账锁和 SQLite 读取事务，避免观察更新与写出交错。不会持有该锁进行网络操作，也不使用 P38 的远端事务操作锁。
- 如果最终核验、同步或会话检查失败，文件可能已在所选路径存在。界面明确要求检查该文件后再选择新名称；计划已消耗，不自动重试或覆盖。
- 原台账、未决安全限制和来源记录均保留。归档不释放容量、不删除/重置/导入证据、不解除未决事务限制，不自动核实远端，也不改变仓库文件或发布内容。浏览器演示四个操作均拒绝。
