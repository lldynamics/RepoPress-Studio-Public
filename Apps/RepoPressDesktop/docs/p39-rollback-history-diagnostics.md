# P39：统一恢复历史与本地诊断

2026-10-02。延续固定 macOS 对照 `origin/main = 2d2858fc5ebc3843d1a281026304c2551741691c`；Linux HEAD 为 `97f1fd75e12b4b9606974890bfa317a7bac9b6e3`，能力判断包含现有未提交工作区。本批继续实施 P38 之后的有界增量，没有重新合并主线。

## 已实现

- P34 时间线现在汇总 Git 推送、PR/MR 和 P38 恢复事务；三种来源分别保留记录 ID 命名空间，每来源最多 200 条、合计最多 600 条，每页展示 50 条。恢复行不能生成另一份恢复计划，可定位到独立的恢复历史及明确只读核实入口。
- 恢复行显示冻结来源 ID/revision/SHA、候选、父提交、源树/目标树、文件计数、最近一次观察及首次精确候选观察。完整来源回执仍保存在 P38 私有持久记录中；时间线仅投影必要字段。P31 来源行被移除后，恢复历史仍可读取。
- 状态按最近一次已记录的观察计算；本地目标变化或无法复核优先显示。首次候选观察只计入独立历史计数，即使后来出现其他头、结果未明或目标变化也不消失。“未决”表示从未精确观察到候选，与“需关注”不同：曾观察候选、后来未明的记录仍需关注，但不计入首次未决。
- 本地诊断显示全局恢复记录容量、当前仓库记录和未决数、已知 URL/分支的未决提示。其他检出仅贡献 `pendingElsewhere` 布尔值，不投影其路径、会话、记录 ID、计划 ID 或尚未在本仓库可见的目标。P31 来源不可用时显示已知目标范围不完整。
- 回滚行与诊断在同一个 SQLite 读取事务中取得；它们构成同一份已提交台账快照。Git 本地目标复验、其他来源和文件系统仍是逐次读取，不构成跨存储原子快照。命令返回前再次确认 session 仍指向同一根目录。
- 明确核实历史记录后会重新读取统一本地台账，即使先前读取尚未结束；旧响应不能覆盖新结果。定位只滚动/聚焦匹配历史行。刷新、读取、定位均不会自动联网、取得凭据、重推或删除记录。

## 容量与失败语义

恢复台账仍使用 P38 的私有存储，不新增数据库或改变持久格式。全局最多 200 条；每条 JSON 最多 65,536 字节，总 JSON 载荷最多 4,194,304 字节。插入为后续观察固定预留 51,200 字节，诊断的新记录剩余空间为 `max(4,194,304 - 实际载荷字节 - 51,200, 0)`。这不是 SQLite 文件或磁盘总占用上限。

容量为：条数达到上限或剩余空间为零时“满”；剩余空间不足最大单条时“有限”；否则“有剩余空间”。即使显示有空间，也不授权写入、不保证具体记录可写入，实际执行仍重新检查。本批修正插入/观察对已有记录重新编码来估计容量的问题，按 SQLite 实际 UTF-8 载荷字节计算；格式不同的有效旧 JSON 不会被低估，观察替换扣除被替换行的实际旧字节。

任一损坏行、超限行、不可用存储使整个恢复来源失败关闭；时间线标记部分来源，诊断计数为空、容量不可用，没有内存兜底或空台账健康结论。诊断不会移除旧意图、丢弃历史候选证据或解除未决分支阻塞。界面校验来源/状态/操作、SHA/时间、三项精确摘要、容量公式及可见目标集合；兼容完全不含 P39 字段的旧双来源快照，并明确诊断不可用。
