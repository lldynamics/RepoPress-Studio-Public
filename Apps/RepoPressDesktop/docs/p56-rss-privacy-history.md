# P56：RSS URL 隐私审阅与历史文章补全

以 `origin/main@878d8cc` 的 macOS RSS OPML 隐私合同和历史补全流程为参照，Linux 已接通 OPML 导入/导出审阅，以及用户触发的历史候选发现、确认、逐篇导入、暂停、恢复与失败重试。RSS 数据仍属于应用级私有数据，与当前仓库会话无关。

## 使用入口与行为

- RSS 侧栏 → OPML：粘贴文档或选择导出，先“审查风险”，再选择“脱敏后执行”或“排除风险订阅后执行”。审阅不改订阅、不发起网络请求，也不提前生成原始导出文本。取消或编辑输入会使旧审阅失效。
- 每个订阅的“补全历史文章”：输入与订阅或站点同源的公开目录地址，设置最多来源页与候选文章数，点击“发现候选文章”。先查看来源和候选，勾选确认后开始补全。关闭、暂停或重启后，需要手动继续；失败项由独立按钮重试。

## OPML 隐私边界

后端同时检查订阅地址、`htmlUrl`，以及标题中嵌入的 HTTP(S) 凭据 URL。风险标题脱敏为站点域名，避免标题字段再次带出地址凭据。检测规则与 macOS 对齐：对解码后的参数名做大小写与符号归一化，识别 token、signature、credential、password、secret、api/access/private key、oauth/auth、key/sig/jwt 等名称，保留 author/authority 等普通参数。重复与百分号编码参数同样检查。

风险预览移除用户信息和片段，隐藏所有查询值，不携带订阅标题。导出脱敏只替换已识别的凭据参数值；排除会跳过整个风险订阅。URL 用户名/密码、无效地址和不符合网络偏好的地址不能直接脱敏执行，必须排除或修正文档。已存订阅的原始 URL 不会因导出被修改。导入保留标题与站点地址，在单个事务中完成，遇到不能安全处理的条目时不留下部分导入。

执行通过 SHA-256 绑定原始导入文本或当前排序后的完整订阅集合以及私网偏好，执行时重新读取并校验；地址、标题、站点或相关偏好漂移要求重新审阅。旧 `rss_import_opml` / `rss_export_opml` 接口遇到风险也会拒绝，避免绕开新界面。原生指纹是可复用的内容绑定，不是一次性服务端票据，每次执行仍强制脱敏或排除。浏览器演示使用最多两个一次性审阅票据，包含标题 URL 检查，解析模块按需加载，执行前同步校验当前状态；历史网络补全在演示中明确不可用。

这是参数名启发式检查，无法识别路径、任意自定义参数名或自由文本中的秘密。RSS JSON/SQLite 备份仍包含敏感本地数据，沿用独立的明文导出确认，不经过 OPML 脱敏。

## 历史补全边界

| 项目 | 本批行为 |
| --- | --- |
| 发现范围 | 手动输入的同源公开目录；识别目录文章链接、下一页、robots 中的站点地图以及默认 sitemap，支持有界嵌套 sitemap |
| 限额 | 默认 10 个来源页、100 个候选；最高 10 页、500 个候选；robots 单独最多 128 KiB，其他响应最多 1 MiB；最多保留 20 个订阅检查点 |
| 网络 | 仅 http/https 公开网络；拒绝查询、用户信息、片段和跨源目标。沿用 DNS 校验、地址固定、连接 peer 检查和禁用环境代理；每次重定向在请求前复验同源与 robots，最多两次重定向 |
| 节流 | 发现请求和重定向间隔至少一秒；文章每个命令处理一个候选，下一请求时间由后端强制。429/503 尊重有界 Retry-After，失败重试仍需显式操作 |
| 来源政策 | robots 不可读取或拒绝时失败关闭；404 表示无 robots 规则。缓存最多五分钟，过期时先刷新政策并把文章请求留到下一步。检查 X-Robots-Tag 与 robots/googlebot meta 的 noarchive/none，扫描超限同样拒绝 |
| 写入 | 发现只保存候选检查点，不导入文章。执行成功后把经过清理的正文写入 RSS；解析常见发布时间和作者元数据。每篇文章与其检查点在同一 SQLite 事务中提交 |
| 去重 | 请求前检查既有 URL，提交前再检查候选、重定向及安全同源 canonical URL；不覆盖既有阅读状态、收藏、标注和正文。普通 RSS 刷新可复用同 URL 的历史记录，避免再产生一份文章 |
| 暂停与并发 | 同一检查点只允许一个在途步骤。暂停改变检查点并使在途响应失效；未提交响应被丢弃。执行前后重新核对订阅绑定，换地址、删除订阅或恢复数据库后旧执行不能写入 |
| 持久化 | `history_jobs` 与 RSS 文章同库；启动将运行态改为暂停，绝不自动发起网络。失败项保留，可手动重试 |

## 数据与备份兼容

RSS 数据库从 schema 2 原子迁移到 schema 3，新增历史检查点表，不重置订阅、文章或阅读数据；未知未来版本拒绝迁移。JSON 导入兼容 schema 2 和 3，恢复时清除待执行历史队列，防止旧候选在恢复后自动执行。JSON 导出不包含队列。SQLite 完整快照同步升级为 schema 3 / 九张表，预览、校验、前端表清单与明文确认已同步；完整快照会包含历史候选和来源政策。

## 并行实施与验收

主线程负责来源与网络约束、数据库迁移、执行事务、公共命令与最终集成。两个 Sol high 工作包分别处理 OPML 和前端，Luna medium 工作包只处理确定性解析。运行时没有旧版 Luna/Terra 组合，因此解析使用可用的 `gpt-6-luna`，需要判断的工作使用 `gpt-5.6-sol`；各包独占文件。完成后另做只读交叉审阅，并修复标题 URL、政策扫描耗尽、发现撤销、robots 限流、canonical 扫描和无 link GUID 去重等边界。

## 后续范围

- 仍需真实 Tauri 桌面、真实站点、Wayland/X11、中文输入法与键盘辅助技术验收；自动测试不代表这些环境已经通过。
- 本批不支持需登录、查询参数分页、JavaScript 渲染、压缩 sitemap 或跨域来源；不能自动扫描整站。来源失败会明确保留部分发现提示。
- 暂停在提交边界取消在途结果，正在进行的 HTTP 请求会在有界超时内结束；发现阶段关闭会通过独立 UUID 撤销，在后续请求、重定向与保存前检查，不再继续剩余发现或发布其检查点。
- 本批不合并 macOS 的斜杠别名探测、既有摘要的选择性全文补抓、发现游标的跨次续扫或检查点维护界面。达到发现/保存上限并不表示历史已全部找齐。
