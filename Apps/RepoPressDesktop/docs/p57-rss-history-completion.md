# P57：RSS 历史文章分段续查与正文补齐

接续 [P56](p56-rss-privacy-history.md)，以冻结的 `origin/main@878d8cc` macOS 源码为参照，补上持久化发现游标、已有摘要的显式全文补抓、经证据验证的斜杠别名，以及检查点维护入口。RSS 仍为应用级私有数据，不依赖当前仓库。

## 使用与同意

RSS 每个订阅的“补全历史文章”先读取本地检查点，打开窗口不会联网。新发现前可明确选择补齐已有文章的缺失或截断正文；该批量选项默认关闭，并随检查点保存。预览区分别显示新文章和已有文章全文，确认后才逐篇请求、导入或写全文缓存。每个候选可能额外访问最多两个同源旧地址，以验证别名。

当前候选处理完、没有失败项时，可以手动“继续发现历史链接”，生成下一段预览，再次确认后写入。关闭、暂停、重启都不会自动恢复网络。失败项必须显式重试成功后才能轮换候选段，避免丢失失败账本。后端和界面都遵守下一请求时间，包括 429/503 的有界 Retry-After。

侧栏“历史补全队列”只读列出最多 20 个检查点，显示来源、累计计数、未决数量和失效状态。清除要再次确认，只删除准确 job 的游标、候选和失败记录，释放检查点槽；文章、缓存、阅读、收藏、标签、高亮和进度保留。运行中、请求在途或正在发现的检查点拒绝清除。失效检查点可明确清除，但不能继续执行。

## 发现与持久化

- 单次最多 1–10 个来源页、1–500 个候选；同一检查点最多处理 10 个完整来源页，待查队列最多 10 个。单页完整身份序列最多 5000 个，累计候选最多 50000 个；超限拒绝，不以截断前缀伪造完整游标。达到上限不代表全站历史已经找齐。
- HTML 与 sitemap 扫描沿用有界响应和解析上限。游标保存来源 URL、完整有序文章 URL 与后续来源队列的 SHA-256 指纹、偏移、pending/visited 队列和累计计数。续查重新请求当前页，最终 URL、文章顺序或后续来源变化均拒绝跳过，保留最后已提交位置。
- 首次网络前先保存空检查点；robots/sitemap 初始化阶段也持久化。之后每个完整来源或候选段原子保存。首次 robots 失败或进程退出后，手动续查仍会完成 sitemap 初始化。取消只丢弃尚未提交的响应，保留此前提交的进度；这是对 P56 一次性发现语义的扩展。
- 同一订阅已有任何检查点时，新发现都拒绝覆盖；需要继续原任务或在队列明确清除。每次提交比较完整旧 payload 和订阅/站点/私网偏好绑定。文章步骤另有随机执行标识，暂停后旧响应不能因同秒恢复而重新生效。

同源、公开网络、无用户信息/查询/片段、逐跳 DNS/peer 校验、禁用代理、robots、noarchive、至少一秒间隔和响应大小限制继续沿用 P56。目录、候选、最终 URL、canonical 与额外旧 URL 都受相同边界约束；不支持登录、查询参数分页、JavaScript 渲染、压缩 sitemap 或跨域发现。

## 全文与身份

已有文章只有在明确启用本批全文补齐、当前来源没有可复用 ready 缓存、正文缺失或有明确摘要/截断迹象时才请求。短但完整的 HTML 不仅因纯文本等于摘要就被判为截断。2026-10-13 P59 复核更正：数据库保存解析器产出的 summary payload，CDATA/文本可以保留 HTML，并非只存纯文本或原始 XML 字节。P57 的实际解析缺口在 Atom XHTML 子树内容丢失；P59 已修复该链路，历史判定继续使用空正文、原 summary/content 相等且短于 1200 字符及截断标记。

成功补齐只在原文章 ID 下原子写入 `full_text_cache` 和历史候选/计数，不更新既有文章整行、阅读状态、高亮、进度、翻译缓存或订阅 validators。当前来源的 ready 缓存零请求复用；失败保留旧缓存；抓取中目标 URL、正文或缓存发生变化时，旧结果不得覆盖并发状态。新增文章和全文成功分别计为“已添加”和“已补全文”。

URL 身份继续保留路径大小写、重复斜杠和尾斜杠。候选、最终地址和安全 canonical 的精确命中沿用 P56；仅有斜杠相似不能判重。新增探测最多检查同订阅前 2000 行中的两个相似旧 URL，只有旧地址的最终重定向或 canonical 与候选证据集合相交，才复用旧文章 ID。无证据时保持独立文章；矛盾身份拒绝写入。

## 兼容与对齐范围

数据库继续使用 schema 3，新增信息只进入带默认值的历史 payload。P56 检查点仍可读取、处理候选和明确清除，但没有经验证的发现游标，不能猜测续扫位置。JSON 恢复继续清空历史队列，完整 SQLite 快照沿用九表合同。

macOS 已有游标续查、正文缓存补齐和旧 URL 证据探测。本批“默认关闭的持久批量全文选择”和“检查点维护 UI”是 Linux 的同意与维护增强；没有宣称逐候选选择、无限扫描或完整 RSS 平台等价。
