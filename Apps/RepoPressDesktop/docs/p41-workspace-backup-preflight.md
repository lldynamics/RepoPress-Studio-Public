## 结果语义与重新核对

- “仅检查文件元数据”表示观察到了白名单文件，不表示 JSON/SQLite 格式正确、引用闭合、正文可读或备份可恢复。损坏内容仍可能得到这一状态；`contentVerified` 与 `consistentSnapshot` 始终为 `false`。
- “未发现持久文件”与“存储不可检查”分别展示。缺失目录或空白名单不等于应用内没有数据，也不把内存降级伪装成持久空库。不可检查时三个计数均为未知，不显示零。
- 未知条目、缺少主文件、条目/字节/时间超限得到部分结果；已知计数是下界，遗漏数量也可能只是“至少”。不会称为完整清单。
- 每份清单绑定选中类别，内存中最多八份，五分钟失效。更改选择、关闭/禁用面板、切换 gateway 或刷新上下文会丢弃旧结果；迟到响应不能回填新范围。
- “重新核对”先消耗旧 ID，再检查相同范围并返回新清单。完整元数据结果区分未变化/已变化；旧清单或新清单任何类别为部分或不可检查时，比较只能是“无法确定”。过期、已消费或丢弃的 ID 不能重试。
- 未变化仅指本批捕获的文件身份、长度、权限及时间元数据一致。它不证明内容相等，不形成跨类别原子快照，也不授权后续复制、清理或恢复。

## 只读与文件系统边界

三个命令为 `inspect_workspace_backup`、`recheck_workspace_backup`、`discard_workspace_backup`。前两项在线程池执行，丢弃只清理内存清单。浏览器演示均明确拒绝，不能展示虚构的私有存储结果。

Linux 通过保留的应用数据目录描述符和逐组件 `openat(O_PATH | O_NOFOLLOW)` 获取元数据，拒绝符号链接、FIFO、非普通文件、多个硬链接、错误所有者和不安全权限。应用数据根必须属于当前用户、不可被组/其他用户写入，身份变化会使整个范围不可检查。类别目录及已知子目录必须为所属用户的私有目录；主文件保持私有权限。SQLite 精确白名单日志文件允许在已验证私有目录内保留默认只读权限位，但拒绝组/其他用户写入或任何执行位；不修改现有数据库或日志权限。

扫描每类最多观察 2,048 个目录项，全部类别共 8,192 个，单文件最多 512 MiB，计入文件长度合计最多 8 GiB，扫描预算五秒。边界值属于本批清单预算，不是可导出大小承诺。扫描后重新核对已观察的目录/文件身份和元数据；期间漂移会使计数未知。限时/超限无法完成复核则仍是部分结果。

预检不读正文、不打开数据库连接、不触发 checkpoint、不创建/迁移存储、不解密聊天、不访问 Secret Service、不读远端、不运行仓库脚本、不删除资料。特别是现有 `KnowledgeLibraryStore.status()` 会触发垃圾清理，本批没有调用它，也没有以原有存储初始化作为检查路径。SQLite 后续导出必须走专门的一致性快照，不能直接复制正在使用的数据库及日志。
