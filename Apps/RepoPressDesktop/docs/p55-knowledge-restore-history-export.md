# P55：恢复历史完整快照导出

P55 接续 [P53 终态归档](p53-knowledge-restore-archive.md)和 [P54 最新历史清理](p54-knowledge-restore-cleanup.md)，为任意已闭合、含完整快照的历史增加手动检查和确认式 JSON 导出。导出包采用既有保存资料包格式，可单独进入 P47 校验、P48 磁盘候选和 P49–P52 的资格、合并与安装计划流程。原历史、当前资料库和活动终态事务的回滚证据保持保留。

## 使用与数据范围

设置中心“恢复历史完整快照 JSON 资料包导出”手动检查最多 4 条历史，选择含完整快照的条目和新的本地 JSON 路径，再生成计划、确认敏感明文导出。可选择旧历史；没有快照的仅日志 cancelled 历史显示为不可导出。检查失败、未知状态或未决事务拒绝计划，不自动修复或继续。

界面显示事务 UUID、终态、归档时间、快照清单摘要与文件计数。导出计划显示目标路径、资源/包数量和大小、原快照清单 SHA-256、去除完成回执后的包清单 SHA-256、JSON 包 SHA-256及有效期，不预览正文、标题、来源网址或原日志。元数据和文件摘要仍属于本地信息。

包保留已保存的正文、离线网页归档、资料历史修订、文件夹、标题、来源网址与保存偏好；资源以可逆 base64 保存，属于敏感明文。completedOperations 清空，固定排除凭据、其他工作区来源、仓库文件、外部引用内容、未引用文件、运行时状态、PDF 原文件及附件原文件。不会联网抓取外部引用；已保存正文中的 URL 和来源 URL 元数据仍保留。原快照和原日志保持原字节。

源快照沿用 P53 的 2048 个资源/64 MiB 与 2 MiB 清单边界；导出兼容 P46/P47 的更小边界：最多 1024 个资源、32 MiB 资源、2 MiB 清单和 48 MiB JSON 包。超限、不完整或完整性未知的网页归档拒绝导出，不截断。当前 DTO 没有单独的清单字节数，2 MiB 清单限制由后端执行；界面严格校验全部已暴露计数、哈希、固定排除项、状态和能力。

导出完成后须独立选择包进行核验并生成候选，再确认所需恢复策略。P55 不直接安装、释放历史容量或回滚整个资料库；后续合并沿用既有身份冲突和新增资料权限重置规则。它不提供 macOS 工作区交换格式、整工作区恢复或覆盖当前冲突身份的历史回滚。

## 路径与一次性计划

目标必须是应用数据根之外、已存在安全父目录内的新绝对小写 .json 文件；拒绝已有文件、链接、特殊节点、Git 工作树/裸仓库祖先和替换的父目录。P55 保守要求目标父目录和应用数据根具有相同 statx mount ID，且二者 inode 身份不同，避免绑定挂载别名绕过路径包含判断；其他 mount、跨盘导出和绑定挂载暂不支持。需要内核提供 mount ID，不能取得时拒绝计划。

应用根身份在 store 创建时固定，每次操作取得固定根描述符和排他 flock。P52 未决恢复、P53 未决归档及 P54 清理意图阻断检查/导出。完整终态 P52 事务可以保留在根目录，导出不会修改其日志和回滚副本。普通当前库编辑不属于历史导出来源绑定，允许在计划后正常编辑，导出继续保留这些编辑。

最多保留 2 份内存计划，墙上时钟和单调时钟共同限制 5 分钟有效期。执行在任何确认、过期、路径或来源检查前消费计划；拒绝确认、时钟回拨、来源漂移或执行失败均不能复用。关闭面板、选择变化、上下文/网关变化和过期会丢弃计划；晚到计划经原网关丢弃。浏览器演示拒绝路径选择和四个原生命令。

## 复验与持久化

检查和计划重复核验全部闭合历史的前序指纹链、记录、原日志、快照引用、完整内容、文件身份和私有权限。选中快照按固定描述符逐文件读取，再核验原树；包复用 P46 的序列化结构并通过 P47 严格格式/内容校验后才生成导出能力。每次执行重新生成同一捕获时刻的包，要求全部字节和摘要匹配计划。

写入使用已有私有不可覆盖导出器：临时文件 0600，写入、文件同步和读回核验完成后，再复验来源、计划、父目录和 Git 祖先；仅通过 persist_noclobber 生成新目标并同步父目录。生成后重新核验来源、根和父目录，并再次读取输出，要求全部字节、完整文件身份、单链接和 0600 权限一致。结果未知或新文件发布后的校验失败保留输出，不自动覆盖、删除、重试或把它当作成功恢复。

历史观察与读取有 30 秒检查点，单文件/JSON 校验沿用既有 5 秒限制，阻塞系统调用没有硬中断保证。来源和输出保持描述符/名称双重检查；同 UID 的非协作进程仍可能在检查与系统调用间制造竞态。导出不是防篡改存储、跨库原子快照或任意断电修复机制。
