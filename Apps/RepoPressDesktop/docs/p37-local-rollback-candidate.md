# P37：隔离的本地逆向提交候选

发布中心的 Git 推送记录新增“准备候选计划”。先完整核验有界目标快照，再展示五分钟有效的一次性计划；用户确认后只在私有临时 Git 目录中生成候选，读回复验并清理。报告保留审阅用 SHA，用户仓库和远端均不写入。

## 已实现范围

- 沿用 P35/P36 的冻结记录、精确版本、仓库/common-dir 身份、唯一有效推送 URL、已核实回执与单父提交条件。根/合并提交、未核实记录、替换引用、目标或证据变化均明确阻塞。P36 变化路径检查必须完整且有实际文件变化；相同树或仅有空子树差异显示没有可生成的变更。
- 对父提交的目标树遍历全部目录与普通文件，包括 P36 跳过的未变化文件。树和 blob 都按原始字节及 Git 类型/长度头核验 SHA-1 或 SHA-256；缺失、损坏、不安全路径、符号链接、gitlink、不支持类型或达到预算，均不能产生可确认计划。不会自动下载对象或跟随链接。
- 差异核验和完整目标树读取共用同一对象缓存与预算：最多 200 条变化路径、200 个目标文件、512 个不同树对象、32 层子目录、单对象 64 KiB、合计对象字节 4 MiB、20 秒。后续生成前后各重新读取该有界快照，隔离构建/读回另有共享 20 秒预算；前后基础条件检查另受既有 Git 超时约束，不将这些阶段之和称为整个请求的 20 秒上限。
- 计划只在内存保留五分钟，最多 8 份、原始对象字节合计最多 32 MiB。准备与生成串行处理以限制临时快照内存；同会话/记录重建计划时移除旧计划，即使新检查被阻塞也不保留旧许可。明确取消、过期清理和一次性生成均释放槽位；重启后重新准备。
- 确认生成时，在检查会话、仓库或到期之前移除计划；错误会话、缺失仓库、过期、证据变化及生成失败均不能重用。生成前和隔离读回后重新读取完整台账、父提交与本地条件，重新构建并比较整份原始对象快照，读取后再次复核记录和目标。
- 临时目录权限为 `0700`，核对当前用户所有权，初始化空模板 bare Git。只将已核验的原始对象通过 `hash-object --stdin` 写入这个目录；没有源仓库 alternates、用户工作树、索引或分支引用。环境与配置来源受隔离，禁用替换、按需下载、全部传输协议、hooks、过滤器和签名配置影响。
- 候选的树精确等于冻结提交父提交的目标树，候选的唯一父提交精确等于冻结 SHA，而不是当前 HEAD。使用固定的审阅作者、UTC 时间和审阅消息构造原始 commit；逐一读回所有写入对象，核对字节、类型、大小和哈希，并检查候选树/单父关系。
- 只有最终证据复验与临时目录显式清理成功才返回成功报告。错误路径释放对象并尝试清理临时目录，清理失败不会声称对象已清理；异常中断仍不能当作持久清理证明。报告没有后续执行令牌或可引用的持久候选对象。
- UI 分两次明确点击，校验完整身份、计划状态、阻塞原因、计数、SHA 宽度、期限和报告对应关系；确认前清除可重用候选，失败须重新准备。取消、过期、关闭、刷新、会话/记录/核实状态/网关变化均清除结果并尽力丢弃旧计划，迟到的计划也丢弃。只给 Git 记录入口，浏览器 demo 三个方法均明确不可用。

## 保留边界与下一步

目标树完整性只指本次有界普通文件快照；没有复制或验证整条提交祖先历史，不宣称完整 `git fsck` 或仓库备份。读取与复验不是跨文件系统原子快照，异常中断也可能留下需要诊断的私有临时目录。候选清理后 SHA 只用于审阅记录，不能当作可立即推送的持久对象。

本批不证明当前远端头、保护分支/写入权限、一般 revert 冲突、整次多提交推送恢复或部署成功；不增加远端执行、命令导出、PR/MR 撤回和持久恢复事务。P35 的确认式远端查询仍独立，候选取消槽位规则也未改动 P35。真实 GitHub/GitLab、真实凭据与故障、原生窗口和桌面发行矩阵仍待验收，本批没有打包或发布发行产物。

下一批建议 P38：远端回滚事务的短时写入计划与持久执行证据，绑定预期远端头、执行前复验和结果不明时的恢复查询；实际写入继续要求独立的明确确认。

同日后续：[P38 确认式远端逆向追加](p38-rollback-transaction.md)已以独立事务复用有界候选构建，增加冻结头条件更新、持久意图和只读恢复查询。P37 本地报告、对象清理及原批次验证边界不变，清理后的审阅 SHA 仍不是执行令牌。
