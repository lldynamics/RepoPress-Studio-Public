# P38：确认式远端逆向追加与持久恢复证据

Git 推送记录增加独立的远端恢复事务。明确点击准备时才查询远端头；完整有界父树、已核实来源和精确远端头均通过后，展示候选 SHA、目标树和五分钟一次性计划。再次确认后，在冻结提交后追加一个恢复其父树的提交。独立的本地恢复台账保存意图与历史观察，重启后可以明确点击只读查询，不自动重试。

## 已实现范围

- 使用 P37 的单父提交和有界普通文件快照条件，包括未变化目标文件、原始对象哈希与完整目标树闭包。根提交、合并提交、未核实来源、不安全路径、特殊类型、缺对象和预算超限不提供执行令牌。200 个变化路径/目标文件、512 个树、32 层目录、单对象 64 KiB、合计对象 4 MiB 等预算沿用 P37；没有扩大为整条历史或一般冲突 revert。
- 准备顺序为完整来源记录/本地条件、完整快照、临时构建/读回候选、明确只读远端查询、再次核验来源及完整快照。只有远端头精确等于来源冻结 SHA 才返回 ready；不同或不可查询均阻塞。计划冻结提交时间、消息和候选 SHA，确认后生成的候选必须完全相同。
- 计划最多五分钟、8 份、原始对象合计 32 MiB；准备、执行与恢复查询串行，SQLite mutex 不跨网络持有。重建同会话/来源时先释放旧计划，取消和过期释放槽位；确认先移除令牌，错误会话、缺失仓库、过期、漂移和失败均消费，不可重放。这是 P38 的独立预算，P37 的本地审阅计划保持原范围。
- 在准备和确认的关键周期持有来源 P31 记录 reservation，阻止并发核实/删除改变整份来源证据。确认过程中复核会话、root/common-dir 身份、唯一有效 URL、整个记录和完整原始快照；凭据仅在明确网络步骤内解析。隔离候选读回、执行前远端复验和最终 TTL/会话/来源检查通过后才可能更新远端。
- 临时 bare Git 为 `0700`，无源 alternates、用户索引或用户引用；复制的原始对象经过哈希与字节读回检查。候选树等于原始父树，候选唯一父提交等于冻结远端头。发送端将已发布来源标记为 shallow boundary，限制 pack 祖先遍历，使用非 thin pack；不读取、复制或下载整条祖先历史。
- 远端写入指定唯一字面 URL 和唯一 `candidate:refs/heads/branch`。使用带完整预期 SHA 的 `--force-with-lease=ref:expected` 做条件更新，另以原始候选的唯一父关系证明被允许的更新是 fast-forward；没有裸 `--force`、`+refspec`、镜像、多分支、标签跟随或子模块递归。远端前进、回退至祖先或删除分支均不能绕过精确预期值；保护分支/服务端规则仍可拒绝。[Git 官方说明](https://git-scm.com/docs/git-push#Documentation/git-push.txt---force-with-leaseltrefnamegtltexpectgt)说明完整 expected 形式的条件语义。
- 任何写请求之前，在独立私有 `rollback-ledger/rollbacks.sqlite3` 写入并同步/读回 `unconfirmed` 意图。保存新回执 ID、plan/session 关联、完整原始 P31 记录、候选/父/两树 SHA、计数和时间；不存 token、正文或原始对象。沿用私有 SQLite 生命周期和进程文件锁，200 条、单条 64 KiB、合计 4 MiB，容量/权限/损坏/锁不可用时拒绝写入，不能退回内存。数据库内复用共享 storage 的 `pushes` 表布局，文件和记录格式与 P31 分离。
- 推送退出码不作为成功回执。写调用返回或失败后只查询一次远端头：精确候选、其他头或未知分别记为 `candidateObserved`、`otherHeadObserved`、`unconfirmed`。其他头或未明不证明没有写入；崩溃、超时、凭据失败、同步失败后的记录仍须通过本地台账诊断。初始未决意图可能在写调用尚未发起时留下，因此也不声称每条记录均已发出请求。
- 首次精确观察到候选的时间单独、单调保存。远端正常前进、后续查询失败和重启不抹去这个历史事实，最新观察仍独立显示。没有精确候选观察的同一字面 URL/分支事务（跨 checkout、worktree 和本应用私有台账内的仓库）阻塞新恢复；同一来源记录本批最多尝试一次，查询其他头不解锁重试。没有自动 retry、凭据更换后自动执行或旧计划恢复。
- 恢复台账独立于来源行展示；原 P31 行删除后，嵌入的完整来源证据仍在。列表与刷新仅读本地，明确点击查询才联网，绑定当前仓库/目标身份和回执 revision。恢复只观察远端，不要求临时候选对象仍存在，也不推送、fetch 或恢复用户工作树。
- UI 显示 URL、分支、冻结/候选/父/树 SHA、计数、期限与范围，区分准备和确认；阻塞原因用中文。计划取消、卸载、过期、上下文变化和迟到响应尽力释放许可。执行成功或失败后只刷新本地恢复台账；历史查询校验完整不可变来源、回执行身份和递增 revision。浏览器 demo 五个方法均明确不可用。

[发布中心](../src/components/PublishCenter.tsx) → [发布台账与手动恢复](../src/components/ReleaseLedgerPanel.tsx) → [恢复面板](../src/components/RollbackTransactionPanel.tsx) → [合同](../src/contracts/rollbackTransaction.ts) / [两份 Gateway](../src/platform/repositoryGateway.ts) → [Tauri 命令](../src-tauri/src/commands/publish.rs) → [事务 Store](../src-tauri/src/core/rollback_transaction.rs) / [独立台账](../src-tauri/src/core/rollback_ledger.rs)。`AppState`、模块导出和 Tauri 注册均接通，无新前端文件访问权限。

准备只接收 `sessionId/recordId/revision`；确认和取消只接收 `sessionId/planId`；恢复查询只接收 `sessionId/recordId/revision`。客户端不能提供执行用 URL、SHA、树、路径或正文。

macOS 比较基线保持 `2d2858fc5ebc3843d1a281026304c2551741691c`。其 GitHub 恢复服务使用父树和冻结提交父关系创建后续提交，GitLab 使用 provider revert。Linux 本批实现有界单冻结 Git 推送的隔离追加与恢复查询，走 Git 传输，不调用 GitHub/GitLab 回滚 API，也不等同于 macOS 的一般 provider revert 或多提交推送恢复。

## 保留边界与下一批

本批未执行真实 RepoPress 远端操作、真实 GitHub/GitLab 凭据/保护规则验收、原生窗口/Wayland/X11/中文输入矩阵、打包或发行。测试远端均为临时 fixture；不能由编译或本地 Git 测试推出真实服务已验收。

候选 SHA 的精确观察只证明那个时刻的分支头，不证明是谁执行、之后保持该头、合并、部署或上线。没有完整一般 revert 冲突处理、整次多提交推送恢复、PR/MR 撤回、工作区恢复、完整祖先备份或抗同账户恶意竞态的跨文件原子快照。shallow 发送端没有复制原始完整祖先；原始父树全部普通文件的预算仍适用。异常中断可能留下私有临时目录，台账不保存可继续发送的 pack 或对象目录。

未决阻塞按字面 URL/分支比较，不识别不同 URL、协议或另一个应用数据目录指向同一服务器仓库的别名；精确头条件更新仍保护本次追加。

本批台账保留全部事务，尚无清理/删除或人工重试解锁；达到容量后拒绝新恢复，普通 P31 发布记录流程保持独立。P39 建议将恢复事务归入统一业务历史，补容量、目标变化和未决事务的本地诊断与定位；保持历史候选观察证据和旧记录不丢失，再独立设计确认式维护/恢复选择。一般冲突恢复、真实服务和桌面发行矩阵继续分批验收。

同日后续：[P39 统一恢复历史与本地诊断](p39-rollback-history-diagnostics.md)已补上第三来源时间线、实际载荷容量和已知目标未决提示、历史记录定位。P38 原事务语义及该批验证记录保持原范围；首证据和旧回执仍保留，没有删除或解锁接口。
