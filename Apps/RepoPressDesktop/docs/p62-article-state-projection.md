# P62 第一阶段：文章状态只读投影与问题定位（2026-10-15）

本批完成 [P62 计划](macos-linux-comparison-2026-10-13.md)的只读阶段，增加文章检查器“文章状态”页、同名写作入口及 `article-state` 命令。通用草稿预览复用紧凑状态显示。状态来自当前编辑内容，不改写 Front Matter，不保存、扫描仓库、查询 Git 或联系部署服务。

## 状态与证据边界

| 当前证据 | 显示 | 含义 |
|---|---|---|
| 已识别站点、文稿位于内容目录内、明确 `draft: true` | 草稿 | 当前文章的草稿意图 |
| 同样归属、明确 `draft: false` | 待发布 | 当前文章的写作意图，不表示日期、部署或全部检查通过 |
| 来源是通用草稿库 | 仅本地 | 不属于任何站点；来源仓库名称只是历史来源信息 |
| 站点/归属无法确认、目录外文件、缺少 draft 或结构不明确 | 状态待确认 | 不猜测缺省状态，不把仓库外文章任意归入通用草稿 |
| 当前 Git/部署台账 | 线上状态：未核验 | 无法绑定到当前文稿版本，不产出“已发布” |

保留 `draft / ready / published / localOnly` 四种状态词汇，但本阶段没有可靠的文稿部署回执，因此不会产出 `published`。Git 推送成功、审阅成功、`status: published`、`draft=false` 或日期到期都不是线上文章已发布的证据。“仅本地”也不代表隐私或文件未被推送。

站点归属使用后端已识别的站点类型、仓库相对内容目录及文稿相对路径；拒绝绝对路径、反斜杠、空路径段和 `.` / `..`，按路径段判断后代关系。只读文稿仍可查看和定位，访问权限按文稿可写标识与应用编辑能力共同判断。

## 有界检查与定位

- 当前编辑内容上限为 256 KiB（UTF-8）；超限时不解析或猜测字段。通用草稿的明确归属独立于正文，不受站点发布字段阻碍。
- 复用既有 Front Matter 读取器，新增只读字段存在性和 UTF-16 范围接口，避免把默认 `draft=true` 当作明确字段。状态投影另外验证保守的单行 YAML/TOML 子集；分节、嵌套、多行、引号键、重复键或无法确认的结构返回待确认，不宣称实现完整 YAML/TOML。
- 明确时区的 ISO 日期时间按真实日历、时间分量与偏移检查，拒绝自动归一化的非法日期。纯日期、无偏移时间和 `-00:00` 保持时区未核验；不借用宿主时区推断。未来日期提示定位问题，到期仍不自动发布。
- 缺失字段打开已有元数据入口，已有日期等问题选择原文完整范围，保留时区、CRLF、BOM、中文和 Emoji 的偏移。定位不会创建字段或改写正文。
- 所有定位及站点/发布入口都先核对上下文键、session、document、保存版本和完整编辑文本。文本变化或同文本保存产生新版本后，旧回调失效；编辑器最终聚焦继续复验导航代际。
- 状态面板延迟加载，只有可见且活跃时计算。语言和无关重绘不重采样时钟或抢焦点；手动刷新、内容/上下文变化或重新进入时重检，没有后台计时或到期提醒。
